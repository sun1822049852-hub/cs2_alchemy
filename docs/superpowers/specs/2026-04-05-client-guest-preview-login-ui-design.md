# 客户端访客预览式登录 UI 设计稿

日期：2026-04-05  
状态：已确认，待进入 implementation plan  
范围：客户端登录 UI、访客态工作区、自动登录、本地会话、受限操作登录浮层  
关系：本设计补充并覆盖 [2026-04-05-client-auth-login-gate-design.md](./2026-04-05-client-auth-login-gate-design.md) 中与“客户端入口方式”和“未登录时的 UI 展现”相关的部分；远端认证契约、邮箱验证码契约仍沿用旧文档。

## 1. 背景

当前项目短期内不要求“必须登录后才能打开客户端”，但需要提前把客户端登录 UI 做出来，为后续接入真实邮箱验证码注册、用户名密码登录、找回密码打基础。

最新确认目标如下：

- 默认启动直接进入工作区
- 若本地已有可用登录会话，则自动登录
- 若没有会话，则进入访客态 `guest`
- 访客态可以浏览所有主页面
- 访客态只显示页面框架、空状态和样例状态
- 访客态不能触发真实业务动作
- 点击受限功能时，在当前页弹出登录浮层
- 当前阶段先做登录 UI 和 mock 行为，不强依赖真实认证后端

## 2. 目标

- 先把客户端登录体验、页面结构和状态流跑通
- 在不阻断当前工作区结构的前提下引入访客态
- 为后续真实认证接入保留稳定的 UI 与状态机边界
- 确保未登录用户看不到真实本地账号、库存、炼金配置、汰换配置

## 3. 非目标

- 本轮不接真实远端认证服务
- 本轮不接真实邮箱验证码发送
- 本轮不实现完整会员权限判定
- 本轮不把未登录用户引导到全屏强门禁页
- 本轮不改动现有主工作区的页面信息架构

## 4. 方案选择

### 4.1 方案A：单壳双态工作区

客户端始终进入同一套工作区壳。  
根据本地会话状态切换为：

- `authenticated`：展示真实数据
- `guest`：展示空状态/样例状态

受限操作统一通过登录浮层拦截。

优点：

- 与现有页面结构兼容性最高
- 后续接真认证时只需替换认证 adapter
- 不需要维护两套页面

缺点：

- 需要梳理各页面的访客态样例与受限操作边界

### 4.2 方案B：接口层统一返回访客样例

前端正常调用所有接口，后端根据未登录状态返回访客样例数据。

优点：

- 权限边界集中在接口层

缺点：

- 当前阶段还不需要真实登录，提前把访客 mock 灌进后端接口会增加复杂度
- 后续清理难度高

### 4.3 方案C：独立游客预览页

为访客专门做一套只读预览页，与正式工作区分离。

优点：

- 首期实现快

缺点：

- 后续维护两套 UI
- 容易与正式工作区漂移

### 4.4 结论

选择方案A。  
后续所有实现均基于“单工作区外壳 + `guest/authenticated` 双态渲染”推进。

## 5. 总体体验

### 5.1 启动体验

启动时客户端进入以下状态流：

`booting -> session_check -> authenticated | guest`

含义：

- `booting`：启动中，只渲染基础 shell
- `session_check`：检查本地是否存在有效登录会话
- `authenticated`：自动登录成功，进入真实工作区
- `guest`：未登录或会话失效，进入访客工作区

### 5.2 用户感知

- 有有效会话时：启动后直接进入已登录工作区
- 无有效会话时：启动后直接进入访客工作区，不显示强拦截全屏 gate
- 访客点击受限功能时：在当前页面弹出登录浮层
- 登录成功后：关闭浮层，留在当前页，切换为真实工作区

## 6. 客户端状态模型

前端统一维护如下状态：

```ts
type ClientAuthMode = "booting" | "guest" | "authenticated";

type ClientSession = {
  username: string;
  display_name: string;
  expires_at: string;
  last_login_at: string;
  status: "active" | "expired" | "guest";
};
```

### 6.1 规则

- `guest` 时不允许保留真实用户页面数据
- `authenticated` 时才允许加载真实用户数据
- 会话失效时必须从 `authenticated` 回退到 `guest`
- 页面组件不直接判断 localStorage，只通过统一状态读取当前模式

## 7. 页面准入与访客态展示

四个主页面都允许访客进入：

- 账号管理
- 库存总览
- 炼金汰换
- 汰换模拟

但访客态不加载真实数据。

### 7.1 账号管理页

保留现有布局：

- 左侧表单
- 右侧已保存账号列表

访客态行为：

- 输入框保持空白，只用于展示
- 不显示真实已保存账号
- 右侧显示 2 到 3 张样例账号卡，并明确标注 `示例`
- 页面说明文案提示“登录后可保存 Steam 账号并绑定到当前客户端身份”

### 7.2 库存总览页

保留现有结构：

- 顶部账号选择与状态区
- 筛选区
- 库存列表区

访客态行为：

- 账号下拉显示 `请先登录`
- 状态显示 `未登录`
- 不加载真实库存列表
- 列表区显示空态或样例卡片
- 筛选控件保留外观，但不驱动真实数据

### 7.3 炼金汰换页

保留现有左右双栏、配方区、快捷选材和执行区。

访客态行为：

- 不加载真实库存候选
- 不加载真实配方和 preset
- 左侧显示样例材料卡
- 右侧显示样例配方和只读执行区
- 执行炼金、添加配方、辅助选材、组件操作等均为受限动作

### 7.4 汰换模拟页

保留现有：

- `已保存配方`
- `选材页面`

访客态行为：

- 已保存区显示样例配方卡
- 工作台显示样例产物与样例材料
- 不读取真实已保存配置
- 搜索、保存配置、编辑配置均为受限动作

## 8. 受限操作与登录浮层

### 8.1 受限操作范围

访客态下，以下行为统一视为受限：

- 登录并保存 Steam 账号
- 连接/刷新库存
- 断开连接
- 执行或暂停炼金
- 组件存入/取出
- 保存、编辑、删除炼金 preset
- 搜索并保存汰换模拟配置
- 任何会触发真实本地状态写入或真实外部请求的动作

### 8.2 交互原则

- 受限按钮保持可见
- 用户点击后不跳页、不清屏
- 在当前页面中央弹出登录浮层

浮层内容：

- 标题：`登录后可用当前功能`
- 副文案：根据来源动作动态变化
- 操作：
  - `去登录`
  - `稍后再说`

### 8.3 登录浮层规则

- 浮层默认显示账号登录面板
- 可切换注册与找回密码
- 登录成功后自动关闭浮层
- 关闭后停留在原页面原位置
- 不自动重放先前动作，避免误触发真实请求
- 登录成功后给轻提示：`已登录，现在可以继续刚才的操作`

## 9. 本地会话与自动登录

### 9.1 启动检查

应用启动后：

1. 进入 `booting`
2. 检查本地会话缓存
3. 若会话有效，则进入 `authenticated`
4. 若会话不存在或过期，则进入 `guest`

### 9.2 登录成功

登录成功后：

- 写入本地会话缓存
- 从 `guest` 切换为 `authenticated`
- 重新拉取真实工作区数据
- 不切换当前页面

### 9.3 退出登录

退出登录后：

- 清理本地会话缓存
- 清空内存中的真实数据引用
- 当前页面直接回落到 `guest` 样例态
- 不跳首页

### 9.4 会话失效

若后续真实接口返回会话失效：

- 当前页提示 `登录已失效，请重新登录`
- 自动回退到 `guest`
- 清空真实渲染数据
- 下次点击受限动作重新弹登录浮层

## 10. 访客样例数据策略

### 10.1 数据来源

新增前端 mock provider，统一提供：

- 样例账号卡
- 样例库存卡
- 样例炼金材料与样例配方
- 样例汰换模拟卡

### 10.2 约束

- 样例数据固定定义在前端 mock 层
- 样例数据不写入真实用户存储
- 样例数据不参与真实计算
- 样例数据只服务于布局与交互展示

### 10.3 切换

- `guest`：只读样例
- `authenticated`：只读真实数据
- 不允许混合展示

## 11. 前端结构拆分

为避免登录逻辑散落在 `app.js` 中，建议拆分为四层：

### 11.1 `authSessionStore`

职责：

- 管理 `booting / guest / authenticated`
- 读写本地会话缓存
- 统一处理自动登录、退出登录、会话过期

### 11.2 `authUiController`

职责：

- 控制登录浮层
- 控制登录入口、顶部用户状态、访客提示文案
- 不直接负责业务页数据装载

### 11.3 `guestPreviewProvider`

职责：

- 提供访客态空状态与样例状态
- 输出页面级样例对象

### 11.4 `workspaceAccessGuard`

职责：

- 统一判定一个动作是否需要登录
- 访客触发时统一弹出登录浮层
- 避免每个按钮各写一份未登录判断

## 12. 当前阶段的 mock 认证策略

当前阶段不接真实远端认证，采用 mock adapter：

- `login(username, password)`
- `sendRegisterCode(email)`
- `register(email, code, username, password)`
- `resetPassword(email, code, password)`

当前行为：

- 可返回 mock 成功
- 可返回 mock 失败
- UI 需要完整体现 loading、成功、错误态

后续接真实认证时只替换 adapter，不重写 UI。

## 14. 测试策略

至少覆盖以下场景：

- 无本地会话时启动进入 `guest`
- 有有效会话时自动进入 `authenticated`
- 访客态不加载真实本地数据
- 访客点击受限按钮时弹出登录浮层
- 登录成功后关闭浮层并保持当前页不跳转
- 退出登录后从真实态回落为样例态
- 会话失效后自动回落为 `guest`

## 15. 验收标准

满足以下条件即视为设计目标达成：

- 默认启动进入工作区，不强拦截
- 未登录时可浏览全部主页面
- 未登录时只能看到空状态/样例状态
- 未登录无法触发真实业务动作
- 受限动作统一弹登录浮层
- 有本地有效会话时可自动登录
- 退出登录和会话失效都能稳定回落到访客态
- 当前阶段无需真实认证后端也能完整演示登录 UI 流程

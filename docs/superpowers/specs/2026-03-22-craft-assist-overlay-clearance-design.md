# 辅助选材浮层避让设计

## 背景

当前炼金页左侧材料区使用了底部浮层式的辅助选材面板：

- 材料列表为 `#craftSelectionList`
- 辅助选材为 `#craftAssistOverlay`
- 浮层通过 `position: absolute` 固定在左侧面板底部

这导致辅助选材拉起后，会直接覆盖材料列表底部区域。用户当前诉求不是“滚一下看起来好一点”，而是：

1. 浮层拉起时，被覆盖的材料要自动向上移动
2. 不允许出现材料被浮层压住的情况
3. 保持现有浮层外观与拖拽高度交互

## 目标

1. 保留当前辅助选材浮层的视觉与交互方式
2. 浮层打开后，材料列表不再被物理覆盖
3. 浮层高度拖拽变化时，材料列表实时同步避让
4. 窗口尺寸变化、列表重绘后仍保持避让生效
5. 修复范围只限于炼金页左侧 UI，不改动辅助选材算法或接口

## 非目标

1. 不重做辅助选材面板结构
2. 不把浮层改为普通文档流面板
3. 不修改 `/api/craft/assist-select` 或后端逻辑
4. 不重做材料列表的数据渲染方式

## 已确认方案

采用“浮层保留 + 列表底部安全区同步”的最小改动方案：

1. 继续保留 `#craftAssistOverlay` 的底部浮层形态
2. 当浮层打开时，给 `#craftSelectionList` 增加一个与浮层高度同步的底部保留区
3. 该保留区不是单纯增加内容内边距，而是占据真实布局空间，让列表可视区域整体上移
4. 当保留区扩大时，自动上推列表当前滚动位置，让用户看到“材料向上移动”
5. 当浮层关闭时，移除保留区，列表恢复原始布局

## 为什么不用其他方案

### 方案一：只自动滚动

只在面板打开瞬间把列表滚一下，无法保证后续拖拽浮层高度、切换分组、再次滚动列表后仍然不遮挡，因此不满足“绝不覆盖”。

### 方案二：改成普通文档流面板

虽然能从结构上彻底消除覆盖，但改动面更大，会影响当前浮层拖拽与整体视觉，风险明显高于本次需求。

## 设计细节

### 1. 列表保留区

在材料列表上新增一个由 JS 驱动的底部保留区高度变量，值为：

`overlayHeight + overlayBottomGap`

其中：

- `overlayHeight` 来自当前辅助选材浮层高度
- `overlayBottomGap` 对应浮层底部与面板边缘的固定间距

CSS 层使用该变量控制材料列表的 `margin-bottom`，让列表自身高度向上收缩，从而避免与浮层重叠。

### 2. 自动上推

当保留区从小变大时，同步提高材料列表 `scrollTop`，让当前底部可见材料整体上移，避免用户看到“原地被切走一截”的突兀效果。

该动作只在保留区增大时触发；保留区缩小时不强制下推，避免关闭面板时产生反向跳动。

### 3. 生命周期挂点

保留区同步逻辑需要挂在以下节点：

1. 辅助选材打开
2. 辅助选材关闭
3. 浮层高度应用时
4. 浮层拖拽移动时
5. 窗口 `resize`
6. 材料列表重新渲染后

这样可以保证 UI 状态变化后，避让状态总是自洽的。

## 测试策略

新增一个前端轻量回归测试，直接从 `node_sidecar/ui/app.js` 提取相关函数，验证：

1. 浮层关闭时，列表保留区为 `0`
2. 浮层打开时，列表保留区等于预期高度
3. 保留区增大时，列表 `scrollTop` 会自动上推
4. 应用浮层高度时，会同步刷新列表保留区

## 风险

1. 由于当前辅助选材默认展开高度很大，列表可视区域可能显著缩小
2. 若保留区同步遗漏某个生命周期，仍可能出现局部遮挡
3. 若滚动上推过度，可能产生轻微跳动

## 风险控制

1. 保留当前浮层高度 clamp 逻辑，不额外放大浮层
2. 把同步逻辑集中到单一 helper，避免多处手写
3. 加入最小回归测试，锁定“打开即避让”“高度变化即同步”这两个核心行为

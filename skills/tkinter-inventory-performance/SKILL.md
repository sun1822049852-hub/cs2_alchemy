# Tkinter 库存卡顿优化

## 何时使用

- 库存页面一次渲染几百条以上卡片，滚动或切换明显卡顿。
- 搜索框每输入一个字符都会卡住 UI。
- 每次刷新页面都在销毁并重建大量 `Frame/Label` 控件。

## 根因判定

优先检查以下两个信号：

1. 全量重建卡片  
每次 `refresh` 都 `destroy` 全部子控件，再按全量数据创建所有卡片。

2. 高频触发刷新  
`<KeyRelease>` 直接调用 `refresh`，导致用户输入时连续触发 UI 重排。

## 推荐优化策略

1. 分页渲染（必须）  
- 卡片视图只渲染当前页，例如每页 `60/90/120/180` 条。  
- 页面切换再渲染下一页。  
- 避免一次创建上千个控件。

2. 搜索防抖（必须）  
- 键盘输入后延迟 `150~250ms` 再刷新。  
- 新输入到来时取消上次待执行刷新任务。

3. 状态可视化（建议）  
- 显示 `匹配数/总数`。  
- 显示 `页码 X/Y`，并动态禁用上一页/下一页按钮。

4. 降低单卡控件复杂度（建议）  
- 避免卡片内过多 Label。  
- 信息分层：常用字段默认展示，次要字段折叠或 hover。

## 实施检查清单

1. 搜索输入绑定是否改为“防抖刷新”而非直接刷新。
2. 卡片渲染是否只使用当前页切片数据。
3. 分页按钮状态是否随页码同步更新。
4. 归类视图是否保留原能力，不受分页影响。
5. 大数据集下切换视图与搜索时是否无明显阻塞。

## 验证方法

1. 用 500+ 物品快照打开卡片视图。  
2. 连续输入搜索关键词，观察是否仍出现输入冻结。  
3. 连续点击下一页/上一页，确认响应时间稳定。  
4. 对比优化前后：CPU 峰值和界面首帧时间应明显下降。

## 新增方案：无限滚动懒加载（替代分页）

- 移除卡片视图中的页码切换控件（上一页/下一页/页码状态）。
- 增加 `batch_size`（每批数量），首屏仅渲染一批卡片。
- 监听 Canvas 的 `yscrollcommand` 与鼠标滚轮事件。
- 当滚动位置接近底部（如 `last >= 0.98`）时，追加渲染下一批。
- 每次追加后更新摘要：`匹配 X/Y，已加载 A，过滤标记 B`。
- 若内容不足一屏（`yview` 为 `0.0~1.0`），自动继续追加直至可滚动或数据耗尽。

### 实施检查清单（懒加载）

1. 卡片视图刷新时是否执行 `reset -> append first batch`，而非全量渲染。
2. 搜索/过滤条件变化时是否重置加载计数并回到顶部。
3. 触底加载是否有并发保护（避免重复触发导致重复渲染）。
4. 分组视图是否保持原逻辑，不受懒加载机制影响。

## 进阶方案：虚拟列表 + 组件复用

- 适用场景：拖拽滚动条速度很快时仍出现白屏/掉帧。
- 核心思路：只维护“可见区域 + 预热区”的卡片控件池，滚动时重绑数据与坐标，不再为每个物品创建控件。
- 实现要点：
  - 使用 `Canvas` 承载卡片窗口，维护固定大小的卡片池。
  - 在 `yscrollcommand`、滚动条 `command`、鼠标滚轮事件里触发虚拟刷新。
  - 按当前滚动位置计算 `start_idx/end_idx`，仅更新该区间卡片内容。
  - 根据总行数动态更新 `scrollregion`。
  - 提供“预热量”参数（如 60/90/120/180），扩大可复用缓冲区，降低快速拖拽白屏概率。

### 实施检查清单（虚拟列表）

1. 列表控件数量是否随库存规模保持近似常量。
2. 快速拖拽滚动条时是否仍能持续看到完整卡片，不出现大面积空白。
3. 搜索、过滤、切换模式后是否会正确重算可见区并刷新。
4. 内存曲线是否较“全量卡片”显著平稳。

## 虚拟列表进一步优化

- 滚动速度自适应预热：
  - 记录滚动速度（px/s），根据速度分档扩大预热行数；
  - 快速拖拽时增加缓存区，慢速时自动回落，平衡流畅度和 CPU 占用。
- 动态卡片高度校准：
  - 在宽度变化或数据集切换后，用样本卡片测量真实高度并平滑更新；
  - 避免长名称换行导致的裁切，同时减少滚动过程中的行高抖动。

### 实施检查清单（进一步优化）

1. 预热行是否随滚动速度动态变化，且有上限保护。
2. 切换窗口宽度后卡片文本是否仍完整显示，无明显裁切。
3. 行高变化是否平滑（无明显跳动），滚动位置是否稳定。

## 高频滚动场景补充优化

- 帧率节流（刷新去抖）：
  - 虚拟刷新限制在约 60fps，避免滚动事件风暴把主线程挤满。
- 紧凑渲染模式：
  - 在高速拖拽阶段仅渲染关键字段（名称、Asset 等），减轻每帧文本重排压力；
  - 停止高速滚动后自动恢复完整字段。
- 增量重绑：
  - 卡片槽位只在索引或渲染模式变化时才重绑文本，避免重复 `Label.configure`。

### 实施检查清单（高频滚动）

1. 快速拖拽时 CPU 峰值是否显著低于无节流版本。
2. 高速拖拽后停止，是否在短时间内恢复完整详情字段。
3. 滚动中是否仍保持连续内容，不出现大面积白屏。

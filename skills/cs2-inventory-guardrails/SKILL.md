# CS2 库存与组件管理防回归 Skill

## 何时使用

- 修改库存刷新、组件存入/取出、会话连接、快照读写、前端交互时。
- 修复“之前能用，改完失效”类型问题时。
- 准备合并较大改动前做一次回归核对时。

## 必守规则（强制）

1. 编码规则
- 所有源码、配置、文案统一 UTF-8。
- 不用 shell 直接写中文源码，中文修改优先 `apply_patch`。
- 出现 `瀛/鍙/缁/�/????` 立即停改，先修编码再继续。

2. UI 与服务边界
- UI 只负责展示和交互，不直接写库存业务逻辑。
- 数据变更只能走后端接口（HTTP/SSE/WebSocket），不在前端“猜状态”。
- 自动刷新由后端调度，前端只接收事件并更新视图。

3. 连接与会话
- 一账号同一时刻只允许一个活动会话。
- 刷新前先检查连接状态；未连接账号禁止组件存取。
- 异常退出后允许会话复用，但必须做状态探活，失败再重建。

4. 刷新时序
- 初次连接：全量刷新（主库存 + 全组件）。
- 后续刷新：前端手动触发 + 后端 30 分钟超时触发。
- 多账号/多库存同时需要刷新时：串行执行，主库存优先。

5. 组件存取规则
- 组件 GC 调用保持串行，避免并发打爆状态机。
- 组件操作队列全局单工（single worker），排队任务可取消。
- 存入前做预筛：不可存物品、隐藏条目、硬编码禁入项直接剔除。

6. 快照规则
- 每个账号的主库存快照只保留最新 1 份。
- 每个账号每个组件快照只保留最新 1 份。
- 新快照写入成功后，立即清理旧快照和孤儿快照。

7. 日志规则
- 默认信息级，调试日志可开关，避免重复刷屏。
- 错误信息必须可读且统一，不允许乱码和歧义文案。
- 对外提示与内部日志文案分层：用户可理解，开发可定位。

## 高频回归点与对应防线

1. 症状：组件数量对了，但组件内物品不显示  
防线：检查是否只取了主库存快照；校验“全组件快照都已落盘”。

2. 症状：只能点击一个目标组件  
防线：目标组件选择控件使用稳定的单选控件；重渲染时保留当前选中值，不重复覆盖。

3. 症状：连接成功但刷新失败  
防线：刷新流程前置连接状态检查，并在失败时给出明确阶段日志（connect / gc / parse / snapshot）。

4. 症状：主程序和 UI 互相抢会话导致 AccessDenied  
防线：统一会话池，禁止同账号多实例同时登录。

5. 症状：改日志后 UI 卡顿、关闭窗口无响应  
防线：日志输出限流；窗口关闭时先停定时器、再停队列、最后断开连接。

## 提交前最小回归清单

1. 连接后刷新：主库存与所有组件数量一致。
2. 主库存/组件切换：视图能切，数据不丢。
3. 存入与取出：各执行 1 次，日志可读无乱码。
4. 自动刷新：30 分钟计时仅对已连接账号生效。
5. 重启后恢复：快照可复用，旧快照已清理。

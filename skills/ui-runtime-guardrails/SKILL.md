# UI 真实运行态防踩坑 Skill

## 何时使用

- 修改前端页面布局、间距、缩放、响应式、自适应高度、overflow、弹层、详情页、卡片视觉时。
- 用户明确要求“直接在浏览器/程序里看真实 UI”，不接受 `companion`、静态样例页时。
- 出现“源码测试通过，但用户截图显示根本没生效”这类冲突时。
- 需要高仿游戏界面、对齐参考图、复刻真实视觉表现时。

## 核心判词

**源码测试通过，不等于 UI 在真实运行态已经生效。**

只要问题落在视觉、布局、缩放、滚动、响应式、交互状态，最终裁决权永远来自：

1. 真实浏览器 / 真实应用界面
2. 运行态 DOM / CSS 证据
3. 用户提供的截图或复现结果

## 必守规则

1. 先跑真实界面，再谈修复  
- 优先启动真实项目页面，不要只读源码猜结果。  
- 用户已明确偏好真实联调时，禁止切回 `companion`、mock 页面、静态原型页充数。

2. 先确认问题落点，再改 CSS/JS  
- 先判断溢出来自哪一层：外层容器、内容区、图片、标题区、按钮区，还是全局缩放。  
- 不允许在没定位 overflow 来源时连续凭感觉改常数。

3. 必须抓运行态证据  
- 至少抓 1 类证据：截图、computed style、`getBoundingClientRect()`、`scrollHeight/clientHeight`、`getComputedStyle()`、class 切换状态。  
- 当用户说“还是没生效”时，以用户截图和运行态数据为准，不能拿源码 diff 反驳用户。

4. 不得把静态断言冒充运行态验收  
- 文本搜索、源码测试、正则断言、静态 snapshot 只能证明“代码里写了”，不能证明“界面上真的生效”。  
- 未经过浏览器/程序运行态验证，不得说“已修复”“已经生效”“经过测试没问题”。

5. 改动后必须回到真实界面复验  
- 每次关键 UI 修改后，回到真实页面查看结果。  
- 如果是缩放/自适应/overflow 类问题，至少验证 1 个目标窗口尺寸与 1 个相邻状态。

## 推荐工作流

1. 进入真实页面并复现目标状态  
- 包括详情页、弹窗、切换态、hover 态、展开态、确认态。

2. 记录当前运行态证据  
- 截图。  
- 容器与内容尺寸。  
- 是否存在纵向或横向 overflow。  
- 当前关键 CSS 变量或 transform 值。

3. 再做最小修改  
- 优先改真正的约束层，不要一上来散弹式修改多个无关选择器。  
- 缩放类问题优先考虑 responsive / viewport-aware 的解法，而不是持续手调 magic numbers。

4. 重新进入真实页面复验  
- 看视觉是否变化。  
- 看运行态数据是否随预期变化。  
- 若无变化，先查选择器命中、层级覆盖、运行时分支与状态机，不继续盲改。

5. 结案前输出证据  
- 说明验证的是哪个页面、哪个状态、哪个窗口尺寸。  
- 若只做了源码级测试，必须明确说“尚未完成运行态验证”。

## 运行态证据清单

- 浏览器截图 / 程序界面截图
- `element.getBoundingClientRect()`
- `scrollHeight` / `clientHeight` / `offsetHeight`
- `scrollWidth` / `clientWidth`
- `getComputedStyle(element)`
- CSS 自定义变量值，如 `--limited-detail-scale`
- 关键节点是否命中选择器、是否处于正确 class / state

## 工具优先级

1. 用户肉眼在真实界面确认
2. 浏览器 DevTools / 程序内真实页面
3. Playwright / 浏览器自动化抓运行态数据与截图
4. 源码静态测试

说明：  
如果源码测试和真实界面冲突，永远以真实界面和运行态证据为准。

## 典型误区

1. “测试通过了，应该已经好了”  
错。那可能只是源码里出现了目标字符串。

2. “scale 算出来了，视觉上肯定会变”  
错。变量可能没命中、被覆盖、被外层容器吞掉，或问题根本不在该节点。

3. “我已经改了 5 个常数，总有一个会对”  
错。连续凭感觉调参只会扩大噪声。

4. “用户截图说没变，可能是他没刷新”  
错。先默认自己没有拿到足够证据，去抓真实运行态数据。

## 完工前最小清单

1. 真实页面已打开并复现目标状态。
2. 至少有一份运行态证据，不只是源码 diff。
3. 已确认变化真实出现在页面上，而不是只出现在代码里。
4. 对缩放/溢出问题，已验证容器尺寸与 overflow 数据。
5. 对外说明时，明确区分“源码测试通过”与“运行态生效”。
